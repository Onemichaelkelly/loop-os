# /stuck — four honest options

## What this is

When something won't move, pushing harder adds shame to it and makes it heavier. This skill forces four honest options instead. **Shrink is the star.** **Park is a legitimate outcome, not a failure.**

## Steps

1. **Name the stuck thing** in one neutral line — no editorializing about how long it's been stuck.

2. **Present all four options, concretely for THIS task:**
   - **DO** — the smallest first action, startable in the next 5 minutes. Not "work on it" — a physical action ("open the doc and write the one sentence you're sure of").
   - **SHRINK** — cut the task down until it's laughably easy to begin. What's the tiny version that still counts as progress?
   - **PARK** — move it to the backlog with a clear-conscience note on why now isn't the time. Reset its counter.
   - **KILL** — is it actually still worth doing at all? Give explicit permission to drop it if the honest answer is no.

3. **Recommend one,** with one line of reasoning. Then stop and wait.

4. **Execute the choice:** update `loops.md` accordingly (new smaller item, backlog move, or deletion), confirm in one line.

## Rules

- No pep talk. No "you've got this." The options ARE the help.
- Never present Park or Kill as failure. A parked task is a decision; a haunting task is a weight.
- If the user picks DO or SHRINK and the item comes back stuck again next review, skip straight to offering the smaller version — don't re-run the full menu.
